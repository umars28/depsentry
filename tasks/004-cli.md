# 004 cli

## Goal

Wire `deps`, `osv` and `report` into the `depsentry` command with the documented exit codes, an overall deadline, and end-to-end fixtures.

`main` calls `run(ctx, args, stdout, stderr, osvURL)` with `https://api.osv.dev` and a context cancelled on Ctrl-C, then exits with its return value. Tests call `run` directly against an `httptest.Server`.

## Related ADRs

- [0002 OSV as the vulnerability data source](../docs/adr/0002-use-osv-as-data-source.md): exit code 2 on network errors.
- [0003 Version resolution](../docs/adr/0003-version-resolution-from-lockfile.md): exit code 2 on a missing or malformed `package.json` or lockfile.
- [0005 OSV client resilience](../docs/adr/0005-osv-client-resilience.md): the overall deadline belongs to the CLI.

## Acceptance criteria

| ID | Criterion |
|---|---|
| AC4.1 | Usage is `depsentry [--timeout <duration>] <project-path>`. No path, more than one path, an unknown flag, or a `--timeout` that is not a positive duration prints usage to stderr and exits 2. `-h`/`--help` prints usage to stderr and exits 0. |
| AC4.2 | `testdata/clean` (lockfile v3, no vulnerable packages): the report goes to stdout, nothing to stderr, exit 0. |
| AC4.3 | `testdata/vulnerable` (lockfile v3, a vulnerable `lodash` and a skipped git dependency): the report shows the CVE and the skipped package, exit 1. |
| AC4.4 | Only non-skipped dependencies are sent to OSV, with the versions from `deps.Resolve`: `testdata/lock-v1` queries the lockfile versions; `testdata/no-lock` queries range base versions and the report marks them `(from range)`. A project whose dependencies are all skipped, or that has none, sends no OSV request and exits 0. |
| AC4.5 | Errors print `depsentry: <message>` to stderr, nothing to stdout, and exit 2: missing project directory, missing or malformed `package.json`, malformed lockfile, OSV non-200 after retries, OSV unreachable. |
| AC4.6 | `--timeout` (default `2m`) bounds the whole OSV phase through the context. A server that never answers makes `run` exit 2 shortly after the timeout. A context that is already cancelled (Ctrl-C) exits 2. |
| AC4.7 | Error text printed to stderr is sanitized like report output (`report.Sanitize` is exported for this), so a hostile `package.json` key cannot inject escape sequences through an error message. |
| AC4.8 | Exit code integrity: exit 0 only when every dependency was resolved and checked and no vulnerabilities were found; exit 1 only when the report was written and has at least one vulnerability. |

## Test changes

- `TestRun_AC4_6_Deadline/hanging_server`: the fake handler slept up to 10 s, and `srv.Close()` waited for it, so the test took 10 s even though `run` returned in about 200 ms. The handler now waits on a channel that is closed in cleanup before the server closes. The assertions are unchanged.
